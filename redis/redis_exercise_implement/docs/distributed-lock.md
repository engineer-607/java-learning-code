# Redis分布式锁与Lua原子解锁

## 1. 问题背景

优惠券秒杀业务需要保证同一用户只能购买一张优惠券。

单机环境可以使用Java锁，但项目启动多个Spring Boot实例后，
不同JVM之间无法共享Java锁，因此需要使用Redis分布式锁。

## 2. 原有问题

原有解锁流程为：

1. GET读取锁中的线程标识；
2. 判断锁是否属于当前线程；
3. DELETE删除锁。

GET和DELETE是两个独立命令，不具有原子性。

可能出现以下时序：

1. 线程A读取到自己的锁标识；
2. 线程A发生阻塞；
3. A的锁过期；
4. 线程B获得同名锁；
5. A恢复执行并删除B的锁。
